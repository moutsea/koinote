## 文件与验证

- [catalog.json](catalog.json)：固定 commit、原作者和链接、许可证文件哈希、全仓文件摘要、采集时 Star 数，以及未收录候选的具体原因。`contentSha256` 是文件按 UTF-8 路径排序后，将每个 `path + NUL + sha256 + LF` 连接起来的 SHA-256。
- [导入脚本](../../scripts/seed_agent_repositories.py)：通过正式的登录、管理员系统容量分配、GitHub 导入和公开接口执行，不直接写数据库、不改变会员资格、不跳过敏感检查。首批公共内容由系统提供容量，不预留或扣减个人空间。
- 下载的原始 ZIP 和 GitHub 元数据保存在本机 `output/agent-repository-curation/`（已被 Git 忽略）。上线导入会重新从 GitHub 获取固定 commit，并核对清单摘要；不依赖这份本地缓存，也不将第三方仓库打包进应用程序。
- 已用这些真实 ZIP 在临时 PostgreSQL 数据库中跑过完整导入、公开、匿名下载全部 8,095 个文件和 Fork；核对了每个下载文件的 SHA-256、原作者、来源链接和许可证。连续执行两次未产生重复仓库；公开目录分页完整展示全部 100 个仓库。

当前状态是**内容和导入流程已准备、通过本地验证**。仓库不会因为提交代码或服务启动而自动公开。生产导入须在共享功能部署后，使用平台专用管理员账号执行下面的操作。

## 上线导入

仓库文件存入专用私有 R2 桶 `koinote-agent-repositories`，服务器数据库仅保存元数据、权限和文件引用。先完成 [R2 配置与迁移](../../docs/AGENT_REPOSITORY_STORAGE.md) 并验证存储访问，再执行这 100 个仓库的导入；系统赠送额度是逻辑容量，不是要求用户另行购买或分配服务器空间。

先预览，不访问服务、不写入：

```sh
python3 scripts/seed_agent_repositories.py
```

这批公共内容由平台提供容量，用户不需要从「我的空间」分配额外空间。导入脚本通过仅限管理员的 `PUT /api/admin/agent-repositories/storage` 为当前平台管理账号补足系统赠送容量（`bonus_bytes`），不增加个人分配量（`allocated_bytes`）。赠送容量至少覆盖完整清单的 199,998,649 字节，同时保留默认 100 MB 额度作为余量；重复执行、分批导入只确保同一个最低额度，不叠加赠送，也不减少已有更高赠送额度。

平台运维应使用已具备仓库写入资格、已启用云端同步的专用管理员账号承载首批内容。获得系统容量的管理员另有 100 个系统仓库名额，在原有 100 个名额之外承载首批内容，保留已有个人仓库。普通用户的名额上限仍为 100；需要拆分时可用 `--only` 分配到多个平台账号。普通用户自行 Fork 后的私有副本仍按个人仓库规则计算。

正式导入仅接受平台管理员的浏览器会话 Cookie，通过 `--cookie-file` 指定安全的本地文件。导入前登录网页取得新的 Cookie 请求头。脚本不再读取 `KOINOTE_DESKTOP_TOKEN`：桌面访问令牌仅有效 15 分钟，无法覆盖完整批量导入；缺少 Cookie 文件时会在访问服务前停止并提示。普通用户会话和仓库/MCP Token 无权分配系统容量。凭据不要放入仓库、命令行参数或聊天记录。

100 个新仓库预计需要约 300 次 GitHub API 请求，超过 [GitHub 匿名访问每小时 60 次的限制](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)。批量导入前，应在管理账号的「我的空间设置」配置只读 GitHub Token；脚本不会接收或另存 GitHub Token。Koinote 每用户每分钟最多导入 5 个仓库、写入 20 次，脚本按 `Retry-After` 等待重试；完整首次导入和发布通常需要二十多分钟。

```sh
python3 scripts/seed_agent_repositories.py \
  --apply \
  --base-url https://your-koinote.example \
  --owner-email curator@example.com \
  --cookie-file /secure/path/koinote-cookie
```

`--owner-email` 必须与当前登录账号一致。脚本先确保系统容量充足，再将全部仓库导入为私有副本并核对内容，然后逐个公开，最后验证匿名访问；成功后会打印各自的 `/repositories/{id}` 链接，可在「Skills/Agent Hub」浏览。首次全量发布按清单逆序执行，使按发布时间倒序展示的目录与精选清单顺序一致；重跑不会刷新已有发布时间。如果先前已发布原有 50 个仓库，新条目会显示在旧条目前方，各批次内保留清单顺序。创建失败时不公开后续内容；公开阶段失败可能已有部分仓库公开，可凭输出确认状态。

固定 `requestId` 使中断重跑复用原仓库；已经公开且内容一致的仓库不会重复发布。若有人编辑过内容，脚本会停止，不覆盖修改。`--apply` 会公开尚未公开的原始副本，包括先前手动撤回的副本，因此撤回后不要再对该条目运行 `--apply`。需要换一批内容时应另建清单，保留旧清单与请求 ID 的对应关系。

可以通过重复 `--only owner/repo` 分批导入或仅重试指定仓库；筛选不会更换 `requestId`，也不会触碰未选中的条目：

```sh
python3 scripts/seed_agent_repositories.py \
  --only cloudflare/skills --only google-gemini/gemini-skills
```

上述命令仍只预览，实际执行时附加前文的 `--apply`、站点和账号凭据参数。撤回某条目后，只选择仍计划公开的仓库执行，避免将它再次公开。

```sh
TEST_DATABASE_URL='postgres://.../disposable_catalog_test?sslmode=disable' \

  go -C backend test ./internal/server -run '^TestCuratedAgentRepositories$' -count=1 -v
```

验证完成后删除临时测试库。此测试验证平台管理员的容量由导入脚本自动赠送，连续两次导入后个人用量与个人分配量仍为零，系统赠送不重复增加；接收 Fork 的普通会员仍通过个人分配获得所需空间。不提高普通账号的默认额度或仓库数量上限。此测试不连接 GitHub、不执行仓库代码；它使用下载的真实内容，通过后端 HTTP 接口和数据库验证上线导入脚本。为避免测试实际等待二十多分钟，测试专用 HTTP 包装器在真实限流器返回 429 后推进内存中的限流窗口，再检查脚本重试恢复；生产限流值不变。
