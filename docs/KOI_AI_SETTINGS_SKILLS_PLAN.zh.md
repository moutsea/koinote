# 我的空间 · Koi AI 设置与 Skills 管理

> 更新日期：2026-11-12。本文保留原需求，并按当前工作区实现收拢说明；不作为生产发布或全面开放的证明。

## 目标与开放范围

用户在「我的空间 → Koi AI」查看服务状态、余额与用量，调整新会话默认权限，并管理账号级技能库。Web 与桌面账号模式使用同一份云端数据；桌面本地模式不请求这些云端接口。

技能安装仍处于灰度：服务端 `KOI_SKILL_TEST_ACCOUNTS` 配置允许使用的 `auth_user_id`，逗号分隔，留空关闭。管理入口受白名单控制，安装、更新和启用还需要终身会员资格；白名单内失去会员资格的账号仍可查看、停用和卸载已有技能。不能将“代码已实现”理解为“所有账号已开放”。

仓库保存源文件，安装清单记录账号选择，启用决定后续任务能否发现，加载表示任务实际使用。收藏、下载、Fork 仓库均不等于安装到 Koi。

## 当前功能

| 入口 | 行为 |
| --- | --- |
| Koi AI 设置 | 展示服务状态、会员与平台管理模型说明；在当前页面展开余额和用量；复用现有新会话默认权限设置及 GitHub 凭据管理 |
| 安装技能 | 文件夹、GitHub、Skills/Agent Hub 三种来源，统一经过解析、预览、选择与确认；确认前展示许可证、兼容范围与警告，说明不扣 Credits、不执行脚本 |
| 已安装技能 | 搜索，按状态及来源筛选，分页，详情与附件预览，启停、卸载和容量展示 |
| 手动更新 | 文件夹重新上传新版本；GitHub、Hub 检查更新后预览并确认，不自动跟踪上游 |
| 会话使用 | 底部聊天与文章侧栏按任务需要发现并加载兼容的已启用技能，展示实际加载记录；文章操作仍受原有文档范围及审核流程约束 |
| 旧库过渡 | 有旧仓库技能的账号先保留 `legacy` 模式，由用户选择迁移或明确使用空安装库；不修改原仓库 |

Koi 基础规则和文档权限不由 Skill 替换。不包含自定义模型渠道、在线技能编辑、自动更新、依赖自动安装，或向本机其他 Agent 写入配置。

## 安装与使用链路

- **文件夹**：选择目录 → 上传与服务端校验 → 查看候选及拒绝原因 → 选择技能 → 确认安装。仅处理用户选择的内容，不保存电脑绝对路径。
- **GitHub**：填写仓库或技能路径及可选 ref → 解析到固定 commit → 校验与预览 → 确认。私有来源复用账号保存的 GitHub 凭据。
- **Hub**：从公开仓库详情安装，无需先 Fork。登录后返回原页面及安装预览，不自动确认；无 `SKILL.md` 时说明没有可安装技能，保留原有 Fork/Clone 功能。
- **失败处理**：没有候选与候选均未通过校验分别提示；保留具体失败原因，未通过校验的预览不能确认安装。
- **旧库迁移**：用户先选择迁移或使用空库，再继续安装；失败不切换技能库。切换到安装库后，不因卸载最后一个技能而恢复仓库自动发现。
- **旧规则**：未开放账号和 `legacy` 模式的底部聊天仍从本人仓库发现技能；文章侧栏不自动发现旧库技能。直接从 Hub 安装属于灰度安装库流程。
- **任务执行**：受理新任务时固定技能库模式、自动发现开关及可用版本；后续启停、更新、卸载影响新任务。缺少可用技能时继续使用基础能力，不要求用户挑选技能。

## 页面直达

设置与技能管理保留在同一页面，以下参数用于定位区域或打开安装弹窗：

- `/space?tab=koi&section=settings`
- `/space?tab=koi&section=skills`
- `/space?tab=koi&section=skills&install=folder`
- `/space?tab=koi&section=skills&install=github`

匿名登录保留目标；关闭安装弹窗后消费 `install` 参数。直达链接遵循相同的灰度、会员和旧库迁移条件，不绕过用户确认。

## 实现与验证入口

- 设置状态及自动技能开关：`/api/koi/settings`；默认权限仍复用 `/api/agent/session-settings`。
- 安装预览与确认：`/api/koi/skill-imports`；清单、详情、附件、启停、卸载与检查更新：`/api/koi/skills`；选择空库：`/api/koi/skill-migration/skip`。
- 数据库迁移为 `0108_koi_skill_storage.sql` 至 `0112_koi_skill_library_mode.sql` 的分批实现，不能恢复旧方案中的同编号整包 SQL。首次安装依赖存储引用保护与配额统计；已产生技能或任务数据后，回退须保留其读取及引用保护。
- 前端按改动运行 `npm run test:koi-settings`、`npm run test:koi-skills`、`node scripts/_check_agent_repository_sharing.mjs` 及 `npm run typecheck:spa`；文案变更补跑 `npm run test:i18n`。
- 后端安装、来源、运行时、迁移与清理回归位于 `backend/internal/server/koi_skill_*_test.go`，数据库测试使用隔离的 `TEST_DATABASE_URL`。通过历史整包测试不代表拆分提交已通过验证，也不等于生产验收。

仓库发布、Fork、Clone 与本机同步见 [Agent Repositories 需求](./AGENT_REPOSITORIES_REQUIREMENTS.zh.md)。
