# 微信公众号中继迁移记录

日期：2026-11-21。运维目标地址与 SSH 材料保存在受保护的配置中。
微信出口 IP 是用户配置公众号白名单所需的公开信息，在指南的共用常量中维护。

## 根因与实际变更

旧中继因安全事件由用户停机。切换前生产 `.env` 和后端运行环境的微信代理均指向
本机端口 1，实测连接失败；网站健康检查正常不能代表微信公众号草稿推送正常。
用户本次指定迁移微信公众号中继，主服务器没有迁移。

- 启用新机上已有的 `koinote-wechat-proxy.service`，只监听 `127.0.0.1:18080`。
  代理只允许 `api.weixin.qq.com:443`，未开放公网代理端口；新机其他微信服务保持原状。
- 在主服务器生成新的专用 Ed25519 客户端密钥，私钥仅保存在主服务器 root 专有目录。
  新中继只接收公钥，授权限制来源主机、代理转发目标，并拒绝该钥匙执行 shell 命令。
  既有管理公钥授权保留。
- 通过已认证管理通道取得新中继主机公钥，固定写入主服务器的专用 `known_hosts`。
  使用仓库中的 SSH tunnel unit 和 root-only `tunnel.env`，隧道由 systemd 开机启动和重连。
- 将主服务器 `.env`、后端容器和 GitHub `WECHAT_API_PROXY_URL` Secret 同步为
  `http://172.18.0.1:18080`。下一次部署仍沿用此内部隧道地址。
  只重建后端容器，保留原镜像和两个生产 Compose 配置；没有执行源码构建。
- 原配置、旧隧道材料和切换前镜像标识保存在主服务器 root-only 的运维备份目录。
  旧中继继续保持停机，没有将它作为故障回退目标。

受影响链路：绑定公众号 → 获取 access_token → 素材/封面上传 → 创建草稿，
这些微信 API 请求共用后端代理配置，经主服务器 SSH 隧道从新中继出站。
AppID、AppSecret 和凭据加密密钥没有因本次 IP 迁移而修改。

四种语言的公开接入指南原先仍指向旧出口，本次改为引用
`spa/src/wechatEgress.ts` 的统一出口地址。截图说明明确其地址只是示例，
应以正文中的当前出口为准，避免复制旧截图中的地址。

## 实际验证

- 新中继本机经专用代理访问微信免鉴权 API，CONNECT 和 HTTP 均为 200。
- 代理转发其他域名被 403 拒绝。
- 腾讯云实例元数据及独立公网出口查询均确认出站 IPv4 与用户提供的新中继 IP 一致；
  新机没有配置全局 IPv6 地址。
- 生产后端容器先使用显式隧道地址、再使用切换后的实际环境变量访问同一微信 API，
  CONNECT 和 HTTP 均为 200；不是模拟网络响应。
- 新隧道 unit 通过真实 `systemd-analyze verify`，隧道运行正常；
  私有配置和客户端私钥权限为 0600。
- 使用新隧道钥匙实际请求 shell 命令被拒绝，转发到非授权端口也被拒绝；
  隧道服务已启用开机启动。
- 切换前核对 Compose 展开的环境与运行容器，无其他待生效环境差异。
  切换时再次核对 `.env`、镜像和 Compose 未发生并发变化；切换后镜像及 Compose 保持一致，
  后端健康接口返回 200。
- 指南文案通过 SPA/Worker 类型检查、站点构建、14 项文档中心检查，以及四语言实际编译值检查。
  公众号相关的 12 项封面传输、70 项草稿和网关流式回归通过；这些回归使用模拟服务，
  不替代下节的真实公众号授权和草稿验收。Worker 发布 dry run 通过。

## 尚未验收的公众号配置

用户确认新中继 IP 尚未加入公众号后台的 API IP 白名单。
每个已绑定公众号都需由管理员分别加入新的实际出口 IP，并移除不再受信任的旧中继 IP。
仅迁移 Koinote 的服务器设置不能自动修改微信平台白名单。

本次没有读取用户 AppSecret、获取真实公众号 access_token、上传用户文章或创建测试草稿。
因此上述网络 200 不能视为真实公众号授权或草稿推送已验收。
管理员保存白名单后，应使用对应公众号完成连接校验，再用指定文章验证草稿推送。
若以后主服务器也更换 IP，还需更新中继公钥授权的来源限制和新主机上的隧道配置。
